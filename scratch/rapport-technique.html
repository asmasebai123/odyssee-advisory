Vue d'ensemble du projet
Contexte & Objectif

Odyssée Advisory est une plateforme juridique SaaS dédiée aux acquisitions immobilières à Dubaï. Elle connecte les avocats du cabinet avec leurs clients investisseurs au travers d'un portail sécurisé et temps-réel.

L'objectif était de créer une application web complète en remplacement d'un workflow papier/email, permettant un suivi des dossiers, la gestion documentaire, la facturation et la communication — le tout dans une interface premium reflétant le positionnement haut de gamme du cabinet.

Modules & Fonctionnalités
Module Authentification
Auth · Infrastructure
Connexion sécurisée

Page de login avec email + mot de passe, validation côté client, protection CSRF. Redirection intelligente selon le rôle (client → /dashboard, avocat → /admin).

Gestion des rôles

Deux rôles distincts : client (investisseur) et avocat (cabinet). Middleware Next.js bloque l'accès aux routes non autorisées.

Création de comptes

L'avocat crée les comptes clients depuis le tableau de bord admin. Un email automatique Resend envoie les identifiants temporaires au client.

Session persistante

Sessions JWT Supabase, rafraîchissement automatique. Déconnexion propre via API route /api/logout.

Portail Client (Espace Investisseur)
Client · 6 Pages
  • Tableau de bord (/dashboard) — Vue d'accueil personnalisée avec salutation, statut du dossier actif, progression en 5 étapes (stepper), actions rapides et derniers documents.
  • Mon Dossier (/dossier) — Vue complète du dossier d'acquisition : timeline des actions, étapes validées, informations propriété, prestation en cours et acteurs impliqués.
  • Documents (/documents) — Liste de tous les documents associés au dossier. Upload de nouveaux fichiers, téléchargement en PDF direct, signature électronique avec pad de signature, menu contextuel (3 points) avec aperçu/télécharger/signer.
  • Messagerie (/messagerie) — Chat temps-réel avec l'avocat. Interface de conversation avec fil de messages, timestamp, envoi de nouveaux messages.
  • Factures (/factures) — Historique des honoraires, statuts (payé/en attente/en retard), téléchargement de chaque facture en PDF imprimable.
  • Paramètres (/parametres) — Gestion du profil client, préférences de notification, informations personnelles.
Portail Avocat / Cabinet (Back-office)
Avocat · 4 Sections
  • Dashboard Admin (/admin/dashboard) — KPIs en temps réel (dossiers actifs, volume conseillé, honoraires facturés, taux de conversion). Nouvelles demandes entrantes. Dossiers récents. Graphiques et indicateurs visuels.
  • Gestion Dossiers (/admin) — Vue tableau de tous les dossiers avec filtres par statut. Création de nouveaux dossiers, assignation de clients, suivi d'avancement. Vue détaillée avec timeline complète d'actions.

  • Gestion Factures (/factures) — Création de factures (honoraires, frais, TVA, devise AED/EUR). Impression PDF avec mise en page officielle du cabinet. Suivi des paiements.
Module Documents — Détail Technique
Full-Stack · Storage
  • Upload — Formulaire drag-and-drop vers Supabase Storage. Métadonnées (nom, type, statut) stockées en base PostgreSQL.
  • Téléchargement PDF — API Route /api/documents/[id]/download qui génère une URL signée Supabase (validité 60s) et force le téléchargement avec en-tête Content-Disposition: attachment.
  • Signature électronique — Modal avec canvas de signature (react-signature-canvas). À la validation, la signature est convertie en image base64 et enregistrée. Le statut du document passe à "Signé" en base.
  • Rendez-vous — Bouton "Réserver un rendez-vous" qui ouvre un formulaire de demande envoyé à l'avocat via API.

Logique & Approche Technique
Sécurité & Protection des Routes
Principe : Chaque groupe de routes est protégé à deux niveaux — le middleware Next.js (vérification JWT côté serveur avant le rendu) et les API Routes (vérification de session à chaque requête API). Un client ne peut jamais accéder aux données d'un autre client.
  • Le middleware intercepte toutes les requêtes sur /(client)/* et /(avocat)/*
  • Chaque API Route vérifie getUser() Supabase avant d'exécuter la requête SQL
  • Les URLs de fichiers Storage sont des URLs signées à durée limitée (60 secondes)
  • Les rôles sont stockés dans la table profiles Supabase et vérifiés côté serveur
Gestion des États & Data Fetching
  • SSR (Server-Side Rendering) — Les pages avocat et client fetchent les données côté serveur avec async/await dans les Server Components, garantissant aucune flash de contenu et un meilleur SEO.
  • Client Components — Utilisés uniquement pour l'interactivité : signature canvas, upload de fichiers, chat messagerie, menus contextuels.
  • Invalidation de cache — revalidatePath() après chaque mutation pour rafraîchir les données sans rechargement complet de page.
  • États de chargement — Skeleton loaders et états disabled sur les boutons pendant les mutations pour un UX fluide.
Design System "Light Luxury"
  • Palette — Fond crème chaud (#FCFAF5), accents or (#C9A26A), barres/sidebar espresso (#221710). Aucun bleu ou couleur générique.
  • Typographie duale — Cormorant Garamond (serif) pour les titres principaux et l'italique dorée des prénoms. Inter (sans-serif) pour le corps de texte et les interfaces.
  • CSS Variables globales — Tout le design système dans :root via globals.css. Les composants référencent var(--gold), var(--ink), etc. — aucune couleur codée en dur dans les composants.
  • Micro-animations — Transitions CSS 0.18s sur tous les états hover/active, effet page-fade à l'entrée de page.
Internationalisation (i18n)
  • Architecture /[locale]/ avec next-intl pour supporter FR, EN, AR (RTL)
  • Fichiers de traduction JSON dans /messages/ — tous les textes UI sont externalisés
  • Le middleware next-intl détecte automatiquement la langue du navigateur
  • Direction RTL automatique pour l'arabe via dir={locale === "ar" ? "rtl" : "ltr"}

Points d'Attention & Évolutions
Emails Resend

Les emails de création de compte sont opérationnels. En environnement de test, vérifier que la clé API Resend est présente dans .env.local.

Stockage de fichiers

Les fichiers sont uploadés dans Supabase Storage. Le bucket documents doit être configuré avec les bonnes policies RLS en production.

Signature légale

La signature électronique actuelle est fonctionnelle pour le MVP. Pour une valeur légale certifiée, intégrer un prestataire qualifié (eIDAS) en phase 2.

Évolutions prévues

Prise de RDV avec calendrier intégré (Calendly/Cal.com), notifications push, espace client multilingue complet, intégration paiement en ligne.

Note sur les polices : La typographie utilise deux polices chargées via next/font/google pour un rendu optimisé sans FOUC. Cormorant Garamond (serif) pour les titres et l'italique dorée des prénoms, Inter pour le corps de texte. Le design system complet est centralisé dans app/globals.css.
